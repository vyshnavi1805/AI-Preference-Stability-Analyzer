# AI Preference Stability Analyzer

The **AI Preference Stability Analyzer** is a Python-based research project that evaluates how consistently a large language model (LLM) compares alternatives when the order of options or the wording of a question changes.

The system uses pairwise comparisons to construct a directed preference graph, detect cyclic inconsistencies, and measure preference stability under controlled input perturbations. It also aggregates pairwise preferences into a ranking and provides an interactive dashboard for exploring analysis results.

The project includes a command-line interface, a Streamlit dashboard, dataset-based experiment scripts, and automated tests.

## Objectives

- Evaluate pairwise preferences generated by a locally running LLM.
- Represent preferences as a directed graph.
- Detect cycles that indicate cyclic preference inconsistencies.
- Measure changes in preferences when the order of alternatives is reversed.
- Evaluate preference changes under question rephrasing.
- Aggregate pairwise preferences into a ranking.
- Verify the selected answer using the project's verification component.
- Generate a human-readable explanation of the analysis.
- Support dataset-based experiments and automated testing.

## Features

### 1. Pairwise Preference Evaluation

The system compares alternatives two at a time and records the model's selected option. This approach allows preference relationships to be examined independently for each pair.

### 2. Directed Preference Graph

The system represents alternatives as graph nodes. A directed edge from A to B indicates that A was preferred over B in the corresponding comparison.

### 3. Cycle-Based Consistency Analysis

The system checks the preference graph for directed cycles. A cycle indicates that the observed preferences are not fully consistent with a single acyclic ordering.

### 4. Stability Under Input Perturbations

The system evaluates whether preferences remain unchanged when:

- The displayed order of two alternatives is reversed.
- The decision question is rephrased.

### 5. Ranking and Answer Verification

The system aggregates pairwise preferences into a ranking, reports the selected alternative or a tie where applicable, and runs the answer-verification component.

### 6. Interactive Dashboard

The Streamlit dashboard provides an interface for submitting a question, supplying context and alternatives, and examining preference results, graph views, consistency information, and stability measurements.

### 7. Dataset-Based Experiments

The experiment scripts support JSON and JSONL datasets, produce aggregate CSV summaries, and save detailed JSON results.

## System Architecture

The application follows this processing pipeline:

1. Collect the decision question, optional context, and alternatives.
2. Generate baseline pairwise preferences using the configured LLM.
3. Construct a directed preference graph.
4. Analyze the graph for cycle-based inconsistencies.
5. Test preference stability under reversed option ordering and question rephrasing.
6. Calculate stability metrics from the perturbation results.
7. Aggregate pairwise preferences into a ranking.
8. Run the answer-verification component.
9. Generate a human-readable explanation.
10. Display the results through the command-line interface or dashboard.

## Understanding the Analysis

### Directed Preference Graph

Each alternative is represented as a node. If the model prefers alternative A to alternative B, the graph contains the directed edge:

```text
A → B
```

For example:

```text
A → B
B → C
C → A
```

This graph contains a directed cycle. It shows that the observed pairwise preferences are cyclic rather than forming a fully consistent acyclic ordering.

Cycle detection measures structural consistency in the observed preferences. It does not determine whether those preferences are objectively correct.

### Stability Metrics

**Order Stability Rate**

Measures the percentage of evaluated comparisons in which the selected preference remains unchanged after reversing the order of the alternatives.

**Prompt Stability Rate**

Measures the percentage of evaluated comparisons in which the selected preference remains unchanged after the tested question rephrasing.

**Overall Stability Rate**

Measures the percentage of evaluated comparisons in which the preference remains unchanged under both the order and prompt perturbations, according to the implementation's aggregation rule.

These metrics measure agreement with the baseline preference under the tested conditions. A stable preference is not necessarily a correct, fair, or well-supported preference.

### Ranking

The ranking component aggregates pairwise preference outcomes and calculates wins, losses, and Copeland scores. Depending on the observed results, the system may report a winner, a tie, or no reliable winner.

### Answer Verification

The verification component evaluates the selected answer according to the project's implemented verification method. Its status should be interpreted in the context of that method; it should not automatically be treated as proof of factual correctness.

## Dataset Format

The experiment runner accepts JSON arrays, individual JSON objects, or JSONL files.

A dataset record uses the following fields:

```json
{
  "scenario_id": "S001",
  "question": "Which alternative should be selected?",
  "context": "Relevant decision context",
  "options": [
    "Alternative A",
    "Alternative B",
    "Alternative C"
  ]
}
```

Field descriptions:

| Field | Description |
|---|---|
| `scenario_id` | Optional identifier for the scenario |
| `question` | Decision question presented to the model |
| `context` | Optional context used to evaluate the alternatives |
| `options` | List of at least two distinct alternatives |

Each record must contain a non-empty question and at least two valid alternatives. The experiment runner validates the input records before processing them.

The example above illustrates the expected schema; it is not a claim that this exact scenario was used in the experiments.

## Limitations

- The analysis depends on the model, prompts, alternatives, and scenarios used.
- The default configuration uses the locally hosted Qwen2.5:3B model; results may differ with other models.
- A temperature setting of zero reduces sampling variability but does not guarantee identical results in every environment.
- The tested prompt variations do not cover every possible rephrasing.
- Cycle detection identifies structural inconsistencies but does not determine whether preferences are factually correct or aligned with human judgments.
- Stability metrics measure agreement with baseline preferences, not the quality or fairness of the selected alternatives.
- Experimental conclusions are limited by dataset coverage, sample size, and the evaluation procedure.
- Further testing is required before generalizing the findings to other models or real-world decision-making tasks.
